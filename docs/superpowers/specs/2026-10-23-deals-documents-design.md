# 取引・帳票機能 設計書

- 日付: 2026-10-23
- 元の依頼: 発注者の「案件・帳票機能 実装仕様」(0〜8章)
- 追加の依頼: 書類確認書(事前準備書)の契約時・決済時を第1段階で作る
- 対象: 仲介・買取再販。リースバックは扱わない(定期借家の新規作成・買戻し・保証委託料・償還表は作らない)

## 0. 進め方の約束

- main で直接作業しない。段ごとに worktree を切り、段ごとに PR を分ける。
- DB の変更は追加だけにする。既存テーブルの列は消さず、変えもしない。本番に入れる前に、変更の中身を発注者に見せて確認を取る。
- 金額の計算はサーバー側の純粋関数にまとめる。金額は整数(円)で扱い、端数の処理は関数ごとに明記する。依頼書3章の例はすべてテストにする。
- 前職の Excel の会社名・氏名・住所・電話番号・文面は使わない。写真の書類確認書も同じで、使うのは項目の構成だけ。
- テストは架空のデータだけで行う。実在の個人情報はリポジトリに入れない。
- 新しい部品(ExcelJS)と、サーバーへの書体の追加(BIZ UD 明朝)は、それぞれ入れる前に発注者の承認を取る。
- PR には毎回、実際の画面で確かめる手順を書く。手順は、開く URL、試す操作、期待する結果の3つ。

## 1. 既存の作りに合わせた読み替え(PR 本文にも書く)

| 依頼書 | この設計 | 理由 |
|---|---|---|
| 「案件」 | 画面の名前は**「取引」**。コード上の名前は `deal` | 既存の「案件ステータス」と混ざらないように(発注者決定) |
| 差し込みタグ付き HTML テンプレート | 書類ごとに **React の部品ファイル(TSX)** を1つ置き、サーバーで HTML にする | 氏名・住所に記号が入っても自動で無害化される。販売図面・手紙と同じ作り |
| 日本語フォント(Noto など) | **BIZ UD ゴシック**(本番に導入済み)と **BIZ UD 明朝**(要承認で追加) | 発注者決定。PDF の中に書体を埋め込む |
| PDF の作り方 | 今ある**サーバー内ブラウザ(Playwright の Chromium)** | 本番で販売図面の PDF を作っている仕組みと同じ |
| Excel の作り方 | **ExcelJS** を新しく入れる | 今の SheetJS(無償版)は数式付きの書き出しに向かない(発注者決定) |
| 会社情報の設定 | 会社名・免許番号・電話・FAX・住所は**今の「会社設定」**をそのまま使う。代表者・口座・ロゴ・角印・文面は取引の設定に足す | 同じ情報を2か所に持たない |
| 物件種別 | 取引ごとに「区分マンション/戸建/土地/一棟」(設定で追加できる)を持つ。既存物件から作るときは物件の種類から自動で当てる | 既存の物件の種類はもっと細かく、帳票の出し分けには粗い分け方の方が合う |
| 物件項目の「住居表示」 | 既存物件の「住所」を当てる | 既存物件に住居表示の専用欄はない |
| 状態などの選択肢 | 文字列の列+アプリ側の許可リスト | 既存の作り方に合わせる(後から選択肢を足しやすい) |
| 不動産取得税の目安(資金計画表) | 手入力。自動では見積もらない | 計算の前提が物件ごとに違い、誤った目安を出すおそれがある |

## 2. データの持ち方

新しいテーブルは5つだけで、すべて追加です。既存テーブルには触りません。

### 2.1 `deals`(取引)

検索・絞り込み・並び替えに使う項目は列にし、それ以外の入力は JSONB にまとめます。

**列**

- 基本: `id`、`deal_no`(年+連番。例 `2026-0001`。一意)、`name`、`business_type`(`brokerage` 仲介 / `resale` 買取再販)、`trade_side`(`seller` 売主側 / `buyer` 買主側 / `both` 両手。買取再販のときは使わず、自社が買主にも売主にもなる)、`status`(`considering` 検討中 / `contracted` 契約済 / `settled` 決済済 / `cancelled` 中止)
- 担当: `assignee_id`(担当者)、`licensed_agent_id`(宅建士)、`sales_staff_id`(営業担当)、`ops_staff_id`(業務担当)。いずれも users への参照で、空欄にできる
- 物件: `property_id`(既存物件。空欄にできる。物件を消したら空欄に戻す)、`property_kind`(`unit` 区分 / `house` 戸建 / `land` 土地 / `building` 一棟、または設定で足した種別)、`has_oc`(真偽値)
- 日時・場所: `contract_at`、`contract_place`、`settlement_at`、`settlement_place`
- 金額: `price`(売買価格・税込)、`building_tax`(うち建物消費税。手で直したら上書きに記録する)、`deposit`(手付金)、`tax_rate_bp`(消費税率。単位は 1/100 %。10% なら 1000。初期値は設定から入れる)
- 管理用: `version`、`created_by`、`created_at`、`updated_at`

**JSONB**

- `property_snapshot`: 物件項目の写し。項目は、物件名、号室、住居表示、所在・地番、家屋番号、種類、構造、築年月、延床面積(専有面積)、土地面積、土地の権利、交通、間取り。既存物件から作ったときも写しを持つ。「物件から取り直す」ボタンで上書きする
- `assessments`: 固都税の評価額の行。筆ごとに、家屋評価額、土地評価額、持分(分子/分母)
- `costs`: 費用。司法書士(名前・住所・連絡先・担当)、登記費用、抹消費用、測量費、その他の自由行(項目名と金額)
- `counterparty_broker`: 相手方の仲介会社・担当・TEL
- `settlement_terms`: 精算条件。固都税(年税額の固定資産税・都市計画税、起算日 1/1 か 4/1)、管理費等(管理費・修繕積立金・その他の月額、前払い月数)、OC の賃料(前受け済みの月数)、敷金の扱い(相殺 / 別途)、その他の精算の自由行
- `leases`: OC の賃貸条件の行。部屋番号、賃借人、契約形態、契約期間、賃料、共益費、駐車場代、その他、預り敷金、滞納の有無・金額、管理会社
- `plan_inputs`: 資金計画表・事業計画書の入力(各段で中身を決める)
- `checklist_state`: 書類確認書のチェック状態と持参物の払い方
- `overrides`: 手で上書きした計算値。キーは計算項目の名前。表示する値は「上書きの値 ?? 計算の値」で、「計算に戻す」でキーを消す

**手入力の物件**: `property_id` を空欄にして、`property_snapshot` だけを持ちます。物件マスタには登録しません。

### 2.2 `deal_parties`(当事者)

- 列は次のとおり: `id`、`deal_id`(取引を消したら一緒に消える)、`role`(`seller` 売主 / `buyer` 買主 / `agent` 代理人 / `tenant` 賃借人)、`party_type`(`individual` 個人 / `corporation` 法人)、`name`、`representative`、`address`、`phone`、`share_num` / `share_den`(共有持分)、`is_self`(自社)、`sort_order`
- 「自社を入れる」ボタンで、会社設定の名前・住所・電話と、取引の設定の代表者を写します。

### 2.3 `deal_documents`(発行履歴)

- 列は次のとおり: `id`、`deal_id`、`doc_type`(書類一覧のキー)、`variant`(購入/売却、社内用/銀行向け など)、`version`(書類の種類ごとに 1 から)、`issued_at`、`issued_by`、`input_snapshot`(JSONB)、`calc_snapshot`(JSONB)、`pdf_key`、`xlsx_key`(どちらも空欄にできる)、`file_base_name`
- 再発行しても前の版は消しません。

### 2.4 `deal_settings`(取引の設定・1行だけ)

- `id = 'singleton'`(既存の設定と同じ作り)
- 中身は次のとおり:
  - 代表者の肩書と氏名
  - 振込先口座(銀行・支店・種別・番号・名義)
  - ロゴと角印の保存キー
  - 文面(あいさつ文・注意事項。書類ごと)
  - 確認書のチェック項目(下の 4.6)
  - 物件種別の一覧
  - 種別×セクションの表示表(事業計画書用)
  - 仲介手数料の方式(上限で計算 / 手入力)
  - `version`
- 消費税率の初期値は、ここではなく税率の表(2.5 の `consumption_tax`)から取る(同じ値を2か所に持たない)

### 2.5 `deal_rate_tables`(税率・税額の表)

- 列は次のとおり: `id`、`kind`、`valid_from`、`valid_to`(空欄なら期限なし)、`content`(JSONB)、`updated_by`、`updated_at`
- `kind` の種類:
  - `consumption_tax`(消費税率)
  - `brokerage_tiers`(仲介手数料の段階と、低廉な空家等の特例の上限)
  - `stamp_contract`(売買契約書の印紙税。金額の区分ごとの本則と軽減後)
  - `stamp_receipt`(領収書の印紙税)
  - `capital_gains`(譲渡所得の税率。長期・短期それぞれの所得税・復興税・住民税、特別控除額)
- 計算に使う表は、**基準日**(契約日、なければ決済日、それもなければ今日)が適用期間に入るものです。
- 現行の値を初期データとして入れます。新しいテーブルに入れるだけです。

### 2.6 ルール

- 保存は、版の番号による楽観ロックで行います。ほかの人が先に保存していたら 409 を返し、画面で「ほかの人が更新しました」と知らせます。
- 変更は既存の変更履歴の仕組み(`recordChangesInTx`)で残します。
- 監査記録には取引の ID・操作・書類の種類だけを残し、氏名・住所・金額は残しません。
- 権限:
  - 新しい権限の種類「取引」(閲覧・編集)を足します。足す場所は、初期データ、付与の SQL、テンプレート権限とユーザー別権限の2画面の一覧、テストの一覧です。
  - 初期値では、全員(現地担当・事務・管理者)に閲覧と編集を付けます。
  - 取引の設定と税率の表は、管理者だけが変えられます。

## 3. 計算(`src/lib/deals/calc/`)

- すべて純粋関数です。DB にも時刻にも触りません。基準日は引数で受け取ります。
- 率は整数で受け取ります(1/100 %。10% なら 1000)。
- 割り算を含む式は、整数のまま掛け算を先にして、最後に1回だけ切り捨てます。小数の誤差で1円ずれるのを防ぐためです。
- 日数は、日本時間の暦の日付で数えます。

| 関数 | 中身 | 端数 |
|---|---|---|
| `brokerageFee(price, tiers, opts)` | 200万円以下の部分 5% + 200万超〜400万以下の部分 4% + 400万超の部分 3%。特例をオンにし、価格が800万円以下なら上限は30万円(税抜)。税込 = 税抜 × (1 + 税率) | 税抜・税込とも円未満切り捨て |
| `prorateAnnualTax(annual, startMonthDay, settlementDate)` | 起算日から1年(うるう日を含めば366日)。決済日から年度末までを買主の負担にする | 買主分 = floor(年税額 × 買主日数 ÷ 年日数)。売主分 = 年税額 − 買主分。起算日が4/1で決済が1〜3月なら注意文と計算期間を返す |
| `prorateMonthly(monthly, settlementDate, prepaidMonths)` | 決済月の月額を日割りし、前払い月数分を加える(管理費等) | 当月分は切り捨て。前払い分は月額 × 月数 |
| `prorateRent(leases, settlementDate, prepaidMonths)` | 賃料・共益費・駐車場代・その他の月額の合計を日割りし、売主から買主へ精算する。前受け済みの月数分を加える | 当月分は切り捨て |
| `depositSuccession(leases, mode)` | 預り敷金の合計と、相殺 / 別途の区分 | 足し算だけ |
| `buildingTaxApportion(price, assessments, landRatioBp, taxRateBp)` | 評価額は筆ごとに「評価額 × 持分」を合計する。土地の評価額には土地の割合を掛ける(初期値100%)。家屋割合 = 家屋 ÷ (家屋 + 土地)。建物価格(税込) = 売買価格 × 家屋割合。建物消費税 = 建物価格 × 税率 ÷ (1 + 税率) | 建物価格・消費税とも切り捨て。手での上書きができる |
| `stampTax(amount, table, kind, opts)` | 契約書は金額の区分で表を引く(軽減は適用期間で切り替える)。折半は ÷2。領収書の非課税は「する / しない / 判断が必要」の3つで、初期値は「判断が必要」 | 折半は切り捨て |
| `loanPayment(principal, annualRateBp, years)` | 元利均等。月利 = 年利 ÷ 12。金利0%なら借入額 ÷ 回数 | 月額は切り捨て |
| `capitalGainsEstimate(input, rates)` | 譲渡所得 = 売却価格 − (取得費 + 譲渡費用) − 特別控除。取得費が分からないときは売却価格の5%。所有期間は売却年の1月1日時点で数え、5年を超えれば長期 | 取得費の5%は切り捨て。課税譲渡所得は1,000円未満切り捨て。税額は税目ごとに100円未満切り捨て。0未満は0。結果に「概算です。正確な税額は税理士にご確認ください」の文を付ける |
| `settlementResult(deal, tables)` | 上の関数を組み合わせた「決済の計算」。精算の各行(項目・計算期間・式の文字列・売主→買主・買主→売主)、合計、差引の1行、残代金 + 精算金 − 敷金承継 = 決済時のお支払額 | 各行は上の関数の端数処理に従う |

**必ず入れるテスト**(依頼書3章の例)

- 3,000万円の仲介手数料 → 税抜 960,000円、税込 1,056,000円
- 400万円を超える価格では「価格 × 3% + 6万円」と一致すること(何点かの価格で確かめる)
- 年税額 120,000円、1/1 起算、決済日 2026-07-01 → 買主 60,493円、売主 59,507円
- 借入 4,000万円、年 1.0%、35年 → 月 112,914円

**ほかのテスト**

- 敷金の承継(相殺 / 別途)
- 建物消費税の按分(持分つきの複数の筆、土地の割合 50%)
- 印紙税(金額の区分の境目、軽減の期限の前後)
- 譲渡所得(取得費が分からない場合、長期と短期の境目、3,000万円特別控除)
- うるう年
- 4/1 起算での注意文
- 月末の決済、月初の決済

`settlementResult` の結果は、次のすべてで同じものを使います。発行するときは結果ごと `calc_snapshot` に保存します。

- 精算書
- 残金決済のご案内の金種明細
- 精算金領収書
- 書類確認書の持参金額

## 4. 書類の作り方

### 4.1 書類の一覧表(`src/lib/deals/documents/registry.ts`)

書類ごとに1行です。1行に書く中身は次のとおりです。

- キー、書類名
- 出す条件(事業区分・物件種別・OC の有無)
- 必要な入力項目(項目の名前と、その項目がある欄)
- ひな形の部品
- 出す形式(PDF / Excel)
- 書体(ゴシック / 明朝)

「書類」タブには、条件に合う書類だけを出します。第2段階の書類は、ひな形を1つと一覧表の1行を足すだけで増やせます。

### 4.2 共通の型

- A4 縦で、余白をそろえます。頭には会社情報を出します。
- 表と数字は BIZ UD ゴシック、領収書・委任状・お知らせは BIZ UD 明朝にします。
- 書体・ロゴ・角印は、データとしてファイルの中に埋め込みます。PDF を作るブラウザは外部の URL を読まない設定のためです。

### 4.3 出す前の確認

- 必要な項目のうち空欄のものを一覧で見せ、「空欄のまま出す」か「入力に戻る」かを選んでもらいます。
- 領収書の非課税が「判断が必要」のままのときも、ここで決めてもらいます。

### 4.4 領収書と署名欄

- 発行者を選べます。
- 売主が個人のときは、その人の名前・住所で出します。自社の角印は付けず、署名・押印の欄は空けます。
- 署名・実印の欄は、どの書類でも常に空欄です。

### 4.5 精算書

- 一度組み立ててから高さを測ります。
- A4 1枚に収まらないときだけ、計算の過程を2枚目の「計算明細」に回します。1枚目には各項目の金額と合計を必ず載せます。
- 当てはまらない行(管理費は区分だけ、賃料と敷金は OC だけ)は出しません。

### 4.6 書類確認書(契約時・決済時)

- 頭に載せる項目は次のとおりです。
  - 取引番号、物件名、売主名・買主名
  - 日時・場所
  - 相手方の仲介会社・担当・TEL
  - 司法書士・担当・TEL
  - 営業担当・業務担当
- 項目は3つのまとまりに分けます。
  - 事前に手配・確認するもの(営業・業務のチェック欄と注意事項)
  - 持参するもの(金額と払い方。払い方は 現金 / 手付金から / 残金から)
  - 受け取るもの(チェック欄・注意事項・メモ)
- チェック項目は設定に持ちます。
  - 最初から、どの会社でも使える一般的な項目を入れておきます。
  - 区分だけ・土地戸建だけ・OC だけの項目は、自動で出し分けます。
  - リースバックの項目は入れません。
- 最後の行は承認欄です。
- 持参する金額には、決済の計算の結果を使います。

#### 4.6.1 謄本の「登記の現況」との連動(追加の依頼 2026-10-24)

物件の謄本(全部事項)から読んだ「今も効力のある登記」(`src/lib/registry-strike/`。PR #558・#562)を、取引と書類確認書に使います。

- 読む元: 取引の物件(`deals.property_id`)に添付された謄本のうち、**全部事項の最新の1件**。PDF から下線(抹消事項)まで読んで判定する(`summarizeRegistryRights`)。手入力の物件・全部事項の添付が無い取引では何もしない。
- 乙区に残っている権利(`activeRights`)があれば:
  - 取引の画面に「抵当権などが残っています(N件)」と、順位・目的・債権額または極度額・権利者を表示する(確認用。取引のデータには書き込まない)。
  - 決済時の書類確認書に、次の項目を自動で出す: 「抵当権抹消書類(金融機関)」の受け取り、「司法書士への抹消の依頼」の事前手配、抹消費用の持参(金額は `costs` の抹消費用)。
- 甲区・乙区に差押え・仮差押え・仮登記などが残っていれば(`cautions`)、取引の画面と書類確認書の頭に注意として出す。
- 判定結果に目視確認の注記(`notes`)があるときは、その注記もそのまま出す。判定できない謄本では、自動で項目を出さず「謄本を確認してください」とだけ出す。
- 判定結果は保存せず、画面を開くたび・書類を出すたびに読む(謄本が差し替わっても古い判定を使わないため)。重いようなら、謄本の添付ID単位で結果を控える仕組みを別途考える。
- 氏名・住所を含むので、取引の閲覧権限と所有者の閲覧権限(`owner:read`)の両方があるときだけ権利者名を表示する。監査記録には件数だけを残す。

### 4.7 PDF

- 今ある PDF の作り方(同時に動かす数の上限、ブラウザが無いときは 503)を使い回します。
- 1ページ目だけを出す今の作りとは別に、何ページにもなる書類用の出し方を足します。

### 4.8 Excel

- 資金計画表・事業計画書では、合計・粗利・利益率・月返済額を Excel の数式で入れます。月返済額の例は `=ROUNDDOWN(PMT(...),0)` です。
- 数式のセルには、サーバーで計算した値も入れておきます。テストでは、この値がサーバーの計算と一致することを確かめます。
- 業務書類は値だけを入れます。

### 4.9 保存と履歴

- ファイル名は `取引番号_書類名_YYYYMMDD` です。日付は日本時間の発行日です。
- ファイルは今の保存場所の `deals/<取引ID>/` に置き、発行履歴に1行足します。
- ファイルを開くときの権限の確認に、取引の種類を足します。取引を見る権限がある人だけが開けます。そうでない人には 404 を返します。保存は控えを残さない設定(no-store)にします。
- 発行したことは監査記録に残します。名前・住所は記録しません。

## 7. テストの方針

- 計算は純粋関数の単体テストで確かめます。3章の例は必ず入れます。
- API は既存の route テストの型で確かめます。確かめる点は、権限、409、変更履歴、監査記録に名前・住所が出ないこと、の4つです。
- 書類は、組み立てた HTML の文字列を確かめます(テスト環境は node)。主な確認点は次のとおりです。
  - 当てはまらない行が出ないこと
  - 署名欄が空欄であること
  - 個人の売主のときに角印が出ないこと
  - 精算書・ご案内・領収書の金額が同じであること
- Excel は、作ったファイルを読み直して確かめます。確かめる点は、数式が入っていること、その値がサーバーの計算と一致すること、の2つです。
- テストのデータはすべて架空のものにします。
- 毎段、型の確認・全テスト・lint・build を通してから PR を出します。
