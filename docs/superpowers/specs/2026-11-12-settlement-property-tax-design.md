# 取引の精算: 固定資産税・都市計画税の作り直し(設計)

2026-11-12・発注者との相談で決めた内容。「(私の案)」は Claude が決めた部分(発注者は全体を「問題ない」で了承済み)。

## 1. なぜ

- 売主が課税業者の取引では、建物分の固都税精算金に消費税がかかる。今は土地・建物の区別が無く(年税額2つを合計して1行で日割り)、建物分も消費税も出せない。
- 実務で困る場面: 売主が課税業者で、手元にあるのが評価証明書だけ(税額は分からない)。評価証明書には土地・建物ごとに「固定資産税課税標準額」「都市計画税課税標準額」が載っている。土地・建物が1つ増えるごとに、その2つが増える。
- 日割りなどの円未満は四捨五入にしたい(今は切り捨て)。

## 2. 目的 / 目的でないもの / やってはいけないこと

目的
- 土地・建物を1つずつ行で足し、行ごとに「固定資産税課税標準額」「都市計画税課税標準額」を入れると税額を自動で出す。税額の箱は手で書き換えられる(税額が初めから分かっているときは箱に直接入れる)。
- 「合計額だけ入れる」入力も残す。ただし「売主は課税業者」の取引では選べない。
- 土地分・建物分をそれぞれ日割りし、課税業者なら建物分の精算金に消費税を足す。
- 日割り(固都税・管理費等・賃料)と消費税の円未満は四捨五入。

目的でないもの
- 免税点(土地30万円・家屋20万円)の判定はしない(私の案)。該当すれば税額の箱を手で直す。
- 市町村ごとの税率の違い(標準税率1.4%以外・都市計画税0.3%未満)には欄を設けない(私の案)。税額の箱を手で直す。
- 物件の「複数の筆・棟」(extra_parcels)から行を自動で作ることはしない(私の案)。行は手で足す。
- すでに発行した書類の控え(発行時の calc スナップショット)は書き換えない。

やってはいけないこと
- 今ある取引の入力(年税額2つ)を消さない・読めなくしない。
- DB の表・列を変えない(migration なし)。保存先は今の `Deal.settlementTerms`(Json)の中。

## 3. 税額の自動計算(公的資料に基づく)

- 税額 = 課税標準額 × 税率。固定資産税 1.4%(標準税率)、都市計画税 0.3%(横浜市の資料)。
- 端数(地方税法 第20条の4の2): 課税標準額の1,000円未満を切り捨て → 税率を掛ける → 税額の100円未満を切り捨て。発注者了承=**税額の自動計算は法律どおり切り捨て、四捨五入は日割りと消費税だけ**。
- 実際の納税通知書は納税者ごとに土地・家屋の課税標準額を合計してから端数処理する(名古屋市の計算例)。この設計は**1行ずつ**計算する(私の案)。数百円ずれたら税額の箱を手で直す。画面にその旨を一言出す。
- 持分(発注者決定=案A): 行ごとに持分(分子/分母・初期値 1/1)を持ち、システムが掛ける。評価証明書の課税標準額が建物全体・敷地全体の額で載っていても、そのまま入れて持分を入れればよい。
- 式(整数で・私の案=持分を掛けてから端数処理): `b = floor(base × shareNum ÷ shareDen ÷ 1000) × 1000`、`tax = floor(b × rateBp ÷ 10000 ÷ 100) × 100`。固定資産税 rateBp=140、都市計画税 rateBp=30。BigInt か整数の順で計算し、浮動小数を通さない。

## 4. 入力(settlementTerms に足すもの)

```ts
taxInputMode: "items" | "total"
taxItems: Array<{
  kind: "land" | "building";
  label: string | null;          // 任意。所在・地番や家屋番号など(100字まで)
  fixedBase: number | null;      // 固定資産税課税標準額
  cityBase: number | null;       // 都市計画税課税標準額
  shareNum: number;              // 持分の分子(1以上・初期値1)
  shareDen: number;              // 持分の分母(分子以上・初期値1)
  fixedTax: number | null;       // 固定資産税の税額を手で入れた値(null=自動の値を使う)
  cityTax: number | null;        // 都市計画税の税額を手で入れた値(null=自動)
}>                                // 最大 40 行(私の案)
sellerTaxable: boolean | null     // null=未設定 → 売主の当事者が自社(isSelf)なら true とみなす(私の案)
```
- 既存の `fixedAssetTax`・`cityPlanningTax`(合計額の入力)と `taxStart` はそのまま使う。
- 読み込み(`readTerms`): 保存済み JSON に `taxInputMode` が無い取引は、年税額のどちらかが入っていれば `"total"`、どちらも空なら `"items"`。新しい取引の初期値は `"items"`(私の案)。
- 行の税額 = 手で入れた値 ?? 自動の値(課税標準額が空なら自動の値は無し=0扱い)。
- 保存の検証: 課税業者(sellerTaxable の実際の値が true)かつ `taxInputMode="total"` は保存を拒む(422。文言「売主が課税業者の取引は、土地・建物ごとに入力してください」)。当事者は zod の型だけでは分からないので API 側で判定する。**止めるのは、保存で固都税の部分(入力のしかた・課税業者・年税額・行)が変わったときだけ**(私の案。OC タブの敷金の扱いや管理費だけの保存は止めない)。物件情報の取り直し(`refresh-property`)・当事者の変更では止めず、精算の欄に注意を出すだけ。
- 課税業者の判定は「sellerTaxable ?? 売主の当事者に isSelf がいるか」。画面ではチェックボックス「売主は課税業者」(未設定なら判定の値で表示し、触ったら明示の値を保存)。
- 起算日(1/1・4/1)は全行共通のまま。

## 5. 精算の行

`taxInputMode="items"` のとき(年税額は行の税額の合計):
| key | 表示名 | 中身 |
|---|---|---|
| `propertyTaxLand` | 固定資産税・都市計画税(土地) | 土地の行の税額(固+都)の合計を日割り |
| `propertyTaxBuilding` | 固定資産税・都市計画税(建物) | 建物の行の税額の合計を日割り |
| `propertyTaxBuildingVat` | 建物分の消費税 | 課税業者のときだけ。建物分の精算金(上書き後の値)× `Deal.taxRateBp` ÷10000、四捨五入 |

- 合計が0の区分の行は出さない(手で直した値があれば出す=今と同じ考え)。
- `taxInputMode="total"` のときは今と同じ1行 `propertyTax`(表示名「固定資産税・都市計画税」)。
- 方向はすべて買主→売主(今と同じ)。
- 手で直す鍵(OVERRIDE_KEYS)に `settlement.propertyTaxLand`・`settlement.propertyTaxBuilding`・`settlement.propertyTaxBuildingVat` を足す(私の案)。既存の `settlement.propertyTax` は合計額の入力のときだけ使う。
- 計算式の欄: 土地・建物は今と同じ形 `年税額円×日数÷年日数`。消費税は `建物分精算金円×10%`(税率は表示用に%)。

## 6. 端数(四捨五入)

- `prorateAnnualTax`: 買主分 = `Math.round(annual × buyerDays ÷ yearDays)`、売主分 = 年税額 − 買主分。
- `prorateMonthly`: 当月分も `Math.round`。
- 消費税: `Math.round`。整数演算で .5 を正しく扱う(浮動小数の誤差に注意: `Math.floor((a*b*2 + d) / (2*d))` の形など)。
- 事業計画の保有コストの日割り(`business-plan.ts` の固都税・管理費)も四捨五入にそろえる(私の案)。
- 売買代金の建物消費税(`buildingTaxOf`)・仲介手数料は変えない(依頼は精算のみ)。

## 6.1 精算金領収書

- 発注者決定: 売主が課税業者なら、領収書は売主が自分で作る=**このシステムの精算金領収書に消費税額・税率・登録番号は載せない**。今の形(内訳の名前を並べて合計額)のまま、行の名前が増えるだけ。印紙の決め方も変えない。控えファイルは新しい行の名前・四捨五入の金額に合わせて作り直す。

## 8. 今ある取引

- 年税額が入っている取引は「合計額だけ」として読み、今までどおり1行で計算する。四捨五入で1円変わることがある。
- 売主が自社(課税業者とみなされる)で「合計額だけ」の今の取引は、画面に「課税業者の取引です。土地・建物ごとに入力し直してください」と出し、固都税の部分を変えて保存しようとすると4章の検証で止まる(管理費だけの保存は止まらない)。計算(表示)は消費税なしで続ける。
