# 販売図面(マイソク)ひな型の自社様式化 — 設計書(フェーズ1: 売マンション)

作成: 2026-07-06 / ステータス: ユーザー承認済み設計(会話で方針・決め事を承認)

## 背景と目的

現行の販売図面エディタは、物件種別ごとに4つのビルダー関数(`build-document.ts`)がA4横のドキュメントを生成し、物件データの一部を自動反映して作成ダイアログの手入力を上乗せする「半自動の下書き」を作る。しかし御社が実際に使うマイソク(Excelテンプレート・出力サンプル3枚で確認)は、はるかに項目が多く・レイアウトも作り込まれた完成様式で、現行ひな型はその一部に留まる。

本件は、**アプリのひな型を御社マイソク様式まで引き上げる**。大きいので段階化し、**フェーズ1で「売マンション」を"見本どおり"に仕上げ、同時に他種別へ横展開できる共通の仕組み(入力方式・選択肢マスタ・レイアウト枠・条件付き行)を整備**する。

参考資料(ユーザー提供): Excelテンプレート(売5種+賃貸2種・選択肢マスタ・会社情報)＋出力3枚(中古マンション×2・売地)。整理成果物: 項目対応表・入力方式マップ5種(会話中のArtifact)。

## スコープ(フェーズ1)

- **売マンション**のビルダー(`buildSaleMansionDocument`)を、御社マイソク様式のレイアウト・全項目・正しい並びに作り直す。
- **共通の仕組み**(以降の種別で再利用):
  1. レイアウト枠(キャッチ帯=上部/写真+セールスポイント+QR=左/間取り枠=中/スペック表=右/会社フッター=下)。
  2. **入力方式モデル**: プルダウン(選択)/入力(数値・自由)/表示切替(あり・なし/課税・不課税)/複数選択(チェック・併記)/自動。
  3. **選択肢マスタ**(御社Excel「物件情報項目リスト」準拠の定数モジュール)。
  4. **作成ダイアログの拡張**: フィールドごとに widget(select/multiselect/toggle/text/number)・単位・選択肢・条件を宣言し、それに沿って描画。
  5. **条件付き行**(表示切替・複数選択の併記)と**自動反映**の配線。
- **自動反映**: 現行で入る項目＋"すぐ配線できる"項目(`Building.totalUnits`→総戸数、`Building.managementCompany`→管理会社)。
- 会社フッターは現行の会社定数(`COMPANY`)を使い、フッターの手入力欄(取引態様・担当者・取引士・特記事項)を作成ダイアログで拾う。

### スコープ外(後続フェーズ・道筋のみ本書末尾に記載)

- **フェーズ2**: 土地・戸建・住宅以外(全部/一部)へ同じ枠で横展開(入力方式マップ確定済)。
- **フェーズ3**: 物件データへの欄追加(価格・交通・土地/建物面積・築年“月”・想定利回り 等)で手入力を自動化。フェーズ1では**これらは作成ダイアログの手入力**のまま(様式に“行”は載せる)。
- **フェーズ4**: 会社情報の設定画面化(現状ハードコード脱却・御社Excelの「会社情報シート」相当)。地図(GPS)・QRの自動生成。用途地域の面積按分表示。
- 賃貸(居住用/事業用)ひな型。DB migration・新規依存はフェーズ1では行わない。

## 決め事(ユーザー承認済み・実装の正)

| 区分 | 決め事 |
|---|---|
| レイアウト | キャッチコピー=**最上部の横帯**(写真・間取りの上／右スペック表の上には**乗せない**)。左=写真グリッド＋セールスポイント(◆箇条書き)＋QR。中=間取り図枠(画像差し込み)。右=スペック表。下=会社フッター。 |
| 価格 | **万円・数値入力・単位固定**(総額)。㎡単価/坪単価も万円。 |
| 消費税 | **課税/不課税を選択**。課税時のみ「うち消費税」(手入力)を表示。※土地は消費税欄なし。 |
| 表示切替(あり/なし) | 借地料・想定利回り(選択で行の表示ON/OFF)。 |
| 複数選択(チェック・**併記**表示) | 地目・接道状況・地域地区・都市計画・用途地域(敷地が境をまたぐ/規制が重なるため)。用途地域の面積按分はフェーズ3。 |
| プルダウン項目 | 会話で確認済み・**修正なしで確定**(選択肢は御社Excelマスタ準拠)。 |
| 自動反映 | 現行で入る項目＋すぐ配線できる分。価格・交通・面積等は当面手入力。用途地域は「自動で1つ→残りチェックで追加」。 |

## アーキテクチャ

### 1. ドキュメントモデル / レイアウト

`document-schema.ts` の `SalesSheetDocument`(`{page, theme, elements[]}`・A4横・要素は mm 座標の絶対配置・種類は text/image/table/badge/shape/qr)は**変更不要**。マンションの版面を、この既存要素で構成する:

- **キャッチ帯**: `shape`(塗り帯・ネイビー)＋`text`(キャッチ)。上部・左〜中央幅(右スペック表の手前まで)。
- **写真グリッド**: `image`×N(左列)。既定枚数と配置はフェーズ1で暫定決め(実物合わせ)。
- **セールスポイント**: `text`(◆区切りの箇条書き)。左・写真の下。
- **QR**: `qr`(左下)。フェーズ1は手動追加でも可・自動生成はフェーズ4。
- **間取り図枠**: `image`(中央・差し込み用のプレースホルダ)。
- **スペック表**: `table`(右列・ラベル/値の行)。本体。
- **会社フッター**: `text`/`shape`(下部帯)。

新しい要素型は不要。レンダラ(`render-html.ts` と `SalesSheetRenderer.tsx` の二重実装)は要素を描くだけなので、**ビルダーが要素を増やせば両レンダラで自動的に描画**される(パリティテスト更新は必要)。

### 2. 入力方式モデル(共通・新設)

種別ごとの版面を、**フィールド定義の宣言的リスト**で表す新モジュール(例 `src/lib/sales-sheet/field-model.ts`)。各フィールド:

```ts
type FieldWidget = "select" | "multiselect" | "toggle" | "text" | "number";
interface SheetField {
  key: string;              // 例 "yotoChiiki"
  label: string;            // 例 "用途地域"
  widget: FieldWidget;
  options?: string[];       // select/multiselect: 選択肢マスタ参照
  unit?: string;            // number: "万円" "㎡" "円/月" 等(固定表示)
  autoFrom?: string;        // 物件データの自動反映元(例 "zoningDistrict")
  toggle?: { onLabel: string; offLabel: string; showWhenOn: boolean };
                            // toggle: 課税/不課税・あり/なし で行の表示ON/OFF
  section: string;          // スペック表の区分(価格/所在/土地/建物/…)
}
```

- **select**: 単一選択プルダウン。
- **multiselect**: 複数選択(チェックボックス)。図面へは**併記**(区切り表示)。対象=地目・接道状況・地域地区・都市計画・用途地域。
- **toggle**: 課税/不課税・あり/なし。`showWhenOn` に応じて対応行(うち消費税・借地料・想定利回り)を出す/出さない。
- **number**: 数値入力＋固定単位。価格=万円固定。
- **text**: 自由/短文入力。設備・条件/備考/特記=自由入力。

この定義を**作成ダイアログ**(入力UI)と**ビルダー**(図面生成)の両方が読む=一箇所で様式が決まる。

### 3. 選択肢マスタ(新設・御社Excel準拠)

`src/lib/sales-sheet/option-master.ts` に、御社Excel「物件情報項目リスト」の選択肢を定数化(マンションで使う分をフェーズ1に、他はフェーズ2で追加):

- 物件種目(マン): 新築マンション/中古マンション/新築タウンハウス/中古タウンハウス/新築リゾート/中古リゾート/その他
- 土地権利: 所有権/(旧法)地上権/(旧法)賃借権/普通借地権(地上権)/定期借地権(地上権)/普通借地権(賃借権)/定期借地権(賃借権)
- 用途地域: 第一種低層〜工業専用/無指定 の全13種(複数選択)
- 建物構造: 木造/ブロック/鉄骨造/RC/SRC/PC/HPC/軽量鉄骨/その他
- 面積計測方式(マン): 壁芯/内法
- バルコニー方向・接道方向: 北/北東/東/南東/南/南西/西/北西
- 接道種別: 公道/私道 ・ 接道位置指定: 有/無
- 駐車場在否(マン): 空有/空無/近隣確保/無
- 管理組合有無: 有/無 ・ 管理形態: 自主管理/一部委託/全部委託 ・ 管理人状況: 常駐/日勤/巡回
- 現況(戸建/マン等): 居住中/空家/賃貸中/未完成 ・ 引渡時期: 即時/相談/期日指定/予定
- 地目: 宅地/田/畑/山林/雑種地/その他 ・ 地勢: 平坦/高台/低地/ひな段/傾斜地/その他
- 都市計画: 市街化区域/市街化調整区域/未線引区域/都市計画区域外/準都市 ・ 地域地区: 防火/準防火/高度/高度利用/風致/文教/その他
- 消費税: 課税/不課税(toggle) ・ 取引態様/報酬形態/広告転載区分(フッター)

### 4. 売マンションの版面(スペック表・確定した並び)

区分ごとの行(入力方式マップ確定版):

- **価格**: 物件種目[select・自動] / 建物名称[text・自動 `Building.name`] / 価格 総額[number 万円] / ㎡単価[number/計算 万円] / 消費税[toggle 課税・不課税]→うち消費税[number 万円・課税時のみ] / 管理費[number 円/月・自動 `managementFee`] / 修繕積立金[number 円/月・自動 `repairReserveFee`]
- **所在・交通**: 所在地[text・自動 `address`] / 交通[text 路線・駅・徒歩分/バス(複数路線可)]
- **土地・権利**: 敷地面積[number ㎡] / 敷地権割合共有持分[text] / 土地権利[select] / 用途地域[**multiselect**・自動1つ+追加]
- **建物**: 専有面積[計測方式 select(壁芯/内法)+number ㎡・自動 `exclusiveArea`] / バルコニー[向き select+number ㎡・自動 `balconyArea`/`orientation`] / 間取り[text/select・自動 `layoutType`] / 建物構造[select・自動 `structureType`] / 所在階[number 階・自動 `floorNo`] / 地上階[number 階・自動 `Building.totalFloors`] / 地下階[number 階] / 築年月[年=自動 `Building.builtYear`/月=number] / 総戸数[number 戸・**自動化 `Building.totalUnits`**] / 駐車場[select] / 駐車場月額[number 円/月]
- **設備・現況・管理**: 設備・条件[text 自由] / その他法令上の制限[text 自由] / 管理組合[select 有/無] / 管理形態[select] / 管理人状況[select] / 管理会社[text・**自動化 `Building.managementCompany`**] / 分譲会社[text] / 施工会社[text] / 現況[select・自動 `occupancyStatus`] / 引渡時期[select] / 備考[text 自由]
- **会社フッター(共通)**: 会社情報[`COMPANY` 定数・自動] / 取引態様[select] / 報酬[select] / 広告[select] / 担当者・取引士[text] / 特記事項[text 自由]

複数選択(用途地域 等)は図面上**併記**(例「第一種住居地域 / 近隣商業地域」)。toggle が off の行(不課税時のうち消費税)は**行ごと非表示**。

### 5. 作成ダイアログ(入力UI)

現行 `SalesSheetCreateButton.tsx` の素朴な `FIELD_SETS`(空文字入力の羅列)を、上記フィールド定義を読むダイアログへ拡張。widget に応じて select/checkbox 群/toggle/number(単位表示)/text を描画。自動反映済みの値は初期表示し(編集可)、手入力欄のみ空で待つ。送信は種別のオーバーライド schema(`new/route.ts`)を拡張して受ける。

### 6. ビルダー(図面生成)

`buildSaleMansionDocument` を、フィールド定義＋物件データ＋ダイアログ入力から**全要素(キャッチ/写真/セールスポイント/QR/間取り枠/スペック表/フッター)**を生成するよう作り直す。条件付き行のスキップ・複数選択の併記・単位付き数値の整形(万円/㎡/円/月)を担う。純関数中心に切り出し、行整形・条件判定・併記結合を単体テスト可能にする。

## テスト方針(TDD・env=node)

- **純ロジック**: フィールド定義→行整形(単位付与・条件スキップ・複数選択の併記結合)・選択肢マスタ整合を RED→GREEN。
- **ビルダー**: マンションの入力(自動＋手入力＋toggle/multiselect)→ 期待する要素集合(スペック表の行・キャッチ/フッターの存在・不課税時にうち消費税行が無い 等)をアサート。
- **レンダラ二重パリティ**: `SalesSheetRenderer.tsx` と `render-html.ts` の出力一致テストを更新。
- **UI**: 作成ダイアログは env=node 制約下で `renderToStaticMarkup` により widget 描画(select/checkbox/toggle/number 単位)を検証。
- ゲート: `tsc` 0 / full `vitest` 緑 / `next build` / eslint 差分0。

## リスクと対応

- **版面の密度**: 項目が多くA4に収めるレイアウト調整が要る。実サンプル(西荻リリエンハイム等)と突き合わせて座標を決める。溢れは省略記法・改行・フォント調整で吸収。
- **二重レンダラのparity**: 要素追加時に両実装＋パリティテストを必ず更新(既知のホットスポット)。
- **自動反映の取りこぼし**: 用途地域は単一データ→複数選択の1つ目に反映、残りは手チェック。フェーズ3で複数対応。
- **会社情報のハードコード**: フェーズ1は許容(現行同様)。フェーズ4で設定化。
- **保存境界**: 生成ドキュメントは既存の `assertSavableDocument`(A4/幾何/z≥0/画像上限)に適合させる。画像(写真)は既存の認可境界に従う。
