# 売却DM文面の外部AI方式(プロンプト出力→貼り付け) 設計

> **作成日**: 2026-08-08 / **性質**: 設計のみ(この PR にコード変更は無い)
> 関連: `2026-08-08-dm-sending-management-design.md`(送付管理)とは独立。並行実装可(migration は直列運用)。

---

## 0. 発注者の方針(2026-08-08)

- 文面の生成は **AI の API 直結をやめる**。システムは**プロンプトだけを出力**し、発注者が手元のブラウザの AI に指示 → 出来上がった本文をシステムに**貼り付けて保存**する。
- **プロンプトと本文をシステムに保存**する(どの指示で作った文面かを後から辿れる)。
- **宛名と住所はシステムが差し込む**(=プロンプトと外部 AI には個人情報を渡さない)。

## 1. 現状(実測)

- 売却DM(キャンペーン→宛先→AI生成→確認→印刷→送付確定)は実装済みだが、**AI 設定(provider+APIキー)未投入で休眠**。生成だけが API 前提で、他の部品は動く。
- **印刷/CSVは本文(body)と宛名(recipientName+敬称)を別々に合成している**(print/route.ts L69-71)。本文に宛名を埋め込む前提が無いため、**共通本文+宛先差込がそのまま成立**する。
- 宛先の氏名・住所・敬称・共有者数は、キャンペーン作成時に drafts の列として確定済み(AI とは無関係に作られる)。
- `sale_dm:generate` 権限と capability `saleDmLetter` は「API 課金があるから」設けられたゲート。

## 2. 設計

### 2.1 外部AIモード(API設定なしで完結)

- キャンペーン作成を **AI 設定なしで可能に**する: 宛先確定までは従来どおり、本文は**空のまま** drafts を作る(status=draft)。
- 既存の「AI で生成」ボタンは AI 設定がある場合のみ表示(従来どおり)。無い場合は外部AIモードの導線だけが出る。

### 2.2 プロンプトの組み立てと表示

- **型(variant)ごと**にシステムがプロンプトを組み立てて表示+ワンクリックコピー。
- プロンプトに含める: 文面の型・トーン・訴求・差出人名・**物件の非PII特徴**(種別・所在は**市区町村+町名まで**。地番・号・部屋番号は含めない)・本文中に使う差込プレースホルダの指定(例「宛名はシステムが差し込むため本文に含めないこと」)。
- **含めない**: 所有者の氏名・住所・電話・法人番号などの PII 全部。
- プロンプト全文は variant に保存(下記 2.4)。

### 2.3 本文の貼り付けと適用

- variant の画面に「本文を貼り付け」欄 → 保存で variant に原本(body_template)を保存 → 「**この型の全宛先に適用**」で variant 配下の drafts の body へ一括セット。
- 上書き保護: **confirmed/sent の draft には適用しない**。既定では **body が空の draft のみ**に適用し、「入力済みの本文も置き換える」チェックを入れた場合のみ draft 状態の全件に適用(個別の手直しを黙って消さない)。
- 個別の手直しは既存の draft 編集をそのまま使う。
- 空本文の draft は確定・印刷に進めない(既存の `body: { not: "" }` ガードと整合)。

### 2.4 schema 変更(additive・migration 1本)

```
dm_variants に追加:
  prompt_text   TEXT?   -- 表示したプロンプトの控え(再現性)
  body_template TEXT?   -- 貼り付けた本文の原本(drafts への適用元)
```

### 2.5 権限

- 外部AIモードに **`sale_dm:generate` は要求しない**(このゲートの根拠は API 課金+PII 外部送信であり、外部モードはどちらも無い)。
- 宛先 PII を扱う点は従来と同じ → `requireSaleDmAccess`(4権限+表示レベル plain)は全操作で維持。貼り付け/適用は書込なので **property:write** も要求(mark-sent と同じ統一方針)。
- capability `saleDmLetter`(AI設定の有無)は「AI で生成」ボタンの表示にのみ影響し、外部AIモードはこれに依存しない。

### 2.6 監査

- 新 action: `sale_dm_prompt_view`{variantId,viewedAt} / `sale_dm_body_paste`{variantId,appliedCount,pastedAt}。detail に本文・プロンプトは載せない(プロンプトは非PII設計だが、detail は件数/ID のみの慣例を維持)。
- `ACTION_EXTRA_KEYS` へ登録。

## 3. 実装の段(PR-D)

送付管理の PR-A〜C とは独立した 1 PR。順序の既定は A→B→C→D だが、発注者が文面運用を急ぐ場合は D を先行できる(依存なし)。

## 4. レビューで特に見てほしい論点

1. プロンプトに載せる物件情報の粒度(市区町村+町名まで、で外部送信の最小化と文面の説得力のバランスが妥当か)。
2. 一括適用の上書き保護(confirmed/sent 除外・個別編集済みの扱い)。
3. `sale_dm:generate` を外部モードに要求しない判断(課金なし・PII 外部送信なしという根拠で十分か)。
4. 空本文 drafts の存在期間(作成→貼り付けまで)に確定/印刷へ漏れる経路が無いか。
