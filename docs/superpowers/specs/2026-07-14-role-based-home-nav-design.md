# 役割別ホーム画面＋役割で出し分けるサイドバー 設計

## 背景 / 目的

現在サイドバーは「管理者かどうか」の1段階でしか出し分けておらず、**現場スタッフ(アルバイト)と事務スタッフが全く同じメニュー**を見ている。現場は現地調査マップしか使わないのに、物件・販売図面・取込まで並び「いろいろなところに飛ぶ」使いづらさになっている。

既存の3ロール `field_staff` / `office_staff` / `admin`(`prisma/schema.prisma` の `Role` enum)を**ナビゲーションの階層**に使い、次の2点を導入する:

1. **役割別ホーム画面** — ログイン後に、その人の役割に合った「大きなカードで行き先を選ぶ」ホームへ着地する(ランチャー方式=ユーザー選択の B 案)。
2. **役割で出し分けるサイドバー** — 前回合意した種別グループ(物件/現地調査/取込・登記/販売図面/売却DM/データ品質/システム管理/資料)を、ログイン中の役割で絞って表示する。

ホームとサイドバーは**併用**(ユーザー選択)。ホームで迷わず入れて、慣れた人はサイドバーで素早く動ける。

## スコープ

### やること
- 新ページ `/home`(役割別のカード・ランチャー)。
- root `/` とログイン後の着地を役割別ホームへ(現在は全員 `/properties`)。
- サイドバーを種別グループへ再構成し、**各項目に「どの役割まで見せるか」**を持たせて役割で絞る。
- サイドバー先頭に「ホーム」導線(全ロール)。

### やらないこと(out of scope)
- 新しい機能画面・新ルート(ホームのカードは**既存ページへのリンク**のみ)。
- 権限(permission)・アクセス制御の変更(これは**ナビの表示可否**であってアクセス制御ではない。権限そのものは不変)。
- DB / schema / migration / 依存の変更。
- ロールの追加・改名。

## 設計

### 1. 役割レベルの共有定義(唯一の正)
新モジュール `src/lib/nav/roles.ts`:
- `type AppRole = "field_staff" | "office_staff" | "admin"`
- `roleLevel(role: string): 1 | 2 | 3` — `field_staff`=1 / `office_staff`=2 / `admin`=3。**未知値・未設定(旧 VIEWER 等、セッションに正規の role が無い場合)は field_staff 相当(1)にフォールバック**(最も制限的＝現地調査＋資料だけが見える安全側。余計なものを出さない)。
- ホーム/サイドバー両方がこの定義を読む。

### 2. サイドバー(役割で出し分け)
`sidebar.tsx` を種別グループ配列へ再構成。各グループ/項目に `minRole`(その項目を見せる最小レベル)を付与し、`roleLevel(userRole) >= item.minRole` の項目だけ描画。グループは可視項目が1つ以上あるときだけ見出しごと表示。

項目 → 最小ロール(確定):
| グループ | 項目 | 最小ロール |
|---|---|---|
| ホーム | ホーム(/home) | field |
| 物件 | 物件一覧・マンション棟 | office |
| 現地調査 | 現地調査マップ・巡回履歴・物件化の完成待ち | field |
| 取込・登記 | 受付帳CSV取込・謄本PDF取込 | office |
| 取込・登記 | 謄本取得の資格情報 | admin |
| 販売図面 | 販売図面を作成 | office |
| 販売図面 | 会社情報(帯設定) | admin |
| 売却DM | 売却DM設定 | admin |
| データ品質 | 所有者点検 6項目 | admin |
| システム管理 | ユーザー管理/権限テンプレ/パスワード変更/権限変更履歴/監査ログ/添付検索 | admin |
| 資料 | 使い方ガイド・取り扱いマニュアル・ヘルプ | field |

- 結果: **現場**=ホーム＋現地調査＋資料。**事務**=＋物件/取込/販売図面(作成)。**管理者**=全部。
- 管理者の長い2グループ(データ品質・システム管理)は現状どおり**折りたたみ**。
- 「ヘルプ」は資料グループへ移す(現状メニュー先頭にあるのを整理)。

### 3. ホーム画面 `/home`
`src/app/(dashboard)/home/page.tsx`(サーバーコンポーネント)。セッションの役割を読み、役割別カードを描画。カードは**各エリアの主画面への Link**。

役割別カード(確定):
- **field_staff**: 「現地調査マップ」を**大カード**で先頭(→ `/field-survey/map`)＋ 巡回履歴(→`/field-survey/sessions`)・物件化の完成待ち(→`/field-survey/candidates`)・使い方ガイド。
- **office_staff**: 物件(→`/properties`)/現地調査(→`/field-survey/map`)/取込・登記(→`/import`)/販売図面(→`/sales-sheets/new`)/資料。
- **admin**: 上記＋売却DM(→`/admin/sale-dm-settings`)/データ品質(→`/admin/owners/correction`)/システム管理(→`/admin/users`)。

カードの可視性も §1 の `roleLevel` ＋ カード定義の `minRole` で決める(サイドバーと同じ定義を共有し二重管理を避ける)。

### 4. ルーティング(着地)
- `src/app/page.tsx`: 現在 `redirect("/properties")` → **`redirect("/home")`** に変更。
- ログイン後の既定遷移が root(`/`)経由なら自動で `/home` に着地。`callbackUrl`(再ログイン導線)がある場合はそれを優先する既存挙動(@codex R3/R4 のオープンリダイレクト対策)を**維持**。ログインページが `/` 以外へ push している場合は `/home` へ変更。
- `/home` は `(dashboard)` グループ配下＝既存の永続レイアウト(サイドバー付き)を継承。

### 5. データフロー / エラー
- 役割はサーバーセッション(`session.user.role`)由来。`dashboard-layout.tsx` は既に `userRole` を Sidebar へ渡している。ホームも同じセッションから読む。
- セッションに `role` が無い/未知値 → **field 相当(最小)** にフォールバック(最も安全＝余計なものを出さない)。ホームは最低限(現地調査＋資料)を表示。
- ホームのカードが指す既存ページの権限は各ページ側で従来どおり検証(ナビは入口の整理のみ)。

## テスト方針
- `roles.ts`: `roleLevel` の写像・未知値フォールバック(純関数・ユニット)。
- サイドバー: 役割別に**出る/出ないグループ・項目**が正しいか(`renderToStaticMarkup` + 文字列 assert。field で「物件一覧」が出ない・admin で「システム管理」が出る 等)。
- ホーム `/home`: 役割別カードの SSR 構造(field で大カード「現地調査マップ」・office で「販売図面」カード・admin で「システム管理」カード)。
- ルーティング: `src/app/page.tsx` が `/home` へ redirect すること(ソース assert or 単体)。
- 提出条件: フル `npx vitest run` 緑 / `tsc` 0 / eslint(変更分)0 / `npm run build` 成功。

## 位置づけ / 依存
- 現在の main(`e90fc26`)を土台とする新機能・新PR。
- **新規依存なし・migration なし・schema 変更なし・権限変更なし。** 並べ替え＋役割で出し分け＋ホーム画面追加のみ＝低リスク。
- UI テストは env=node 制約により SSR 構造＋自明変更＋レビューで担保(クリック/state 遷移の単体テストは書かない)。
