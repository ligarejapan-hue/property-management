# 作業中の入力を、別のメニューへ移っても消さない — 設計書

- 日付: 2026-10-13
- 発注者の要望: 「ある作業中に別のメニューに飛び、戻るとすべて消されている状況を変えたい」(対象=入力していたり、ファイルを読み取ったりした画面)
- 方式: 発注者が3案から **A(入力途中をそのタブの中に自動でとっておき、戻ったら復元する)** を選択(2026-10-13)。設計の要点も同日了承。

## 1. 目的と成功の条件

- 作業の途中で別のメニューへ移り、戻ってきたときに、**入力・読み取り結果・進み具合がそのまま残っている**。
- 戻ったとき、続きを表示していることが分かり、**ワンタッチで捨てて最初からやり直せる**。
- 所有者の名前・住所などを**パソコンにいつまでも残さない**(タブを閉じる/ログアウト/作業完了で消える)。
- **二重登録を起こさない**(送った結果が分からないまま離れた作業を、戻ったときに再送できる状態で復元しない)。

やらないこと(YAGNI): 別のタブ・別の端末で続きをする/サーバーへの下書き保存/ファイル本体の保持/離れる前の確認ダイアログ。

## 2. 対象の画面

| # | 画面 | とっておくもの | ファイル本体 |
|---|---|---|---|
| S1 | 貼り付けて物件化 `import/paste/page.tsx` | 貼った文章・読み取り結果(下書き・重複/似た物件・所有者候補・抽出文)・直した値(物件/所有者/メモ/外部キー/所有者の扱い/棟の選択) | PDFを添付する場合は登録時に要る→**選び直し** |
| S2 | Excelから物件化 `import/paste/excel/page.tsx` | 読み取った行・行ごとの結果・**送信中の行** | 読み取り後は不要 |
| S3 | 謄本PDFの取り込み `import/registry-pdf/page.tsx` | 段階(upload/extract/confirm)・タブ・貼った文章・ファイル名・読み取った欄/所有者/警告・取り込み先(新規/既存の物件ID・検索語) | ファイルで読んだ場合は取り込み時に要る→**選び直し** |
| S4 | 取り込み(CSV) `import/page.tsx` | 段階(1〜3)・ファイル名・中身(文字/base64)・見出し/行・列の対応・テンプレート・重複の下見。受付帳×所有者/受付帳→物件の2つの流れも同様 | 中身を文字で持っているので不要(大きすぎる場合は §5.4) |
| S5 | 物件の編集(小窓) `properties/property-edit-form.tsx` | **変えた欄だけ**+基にした版番号 | 無し |
| S6 | 新規物件登録(小窓) `properties/new-property-modal.tsx` | 種別・郵便番号・住所・地番・物件名・部屋番号・紹介経路・メモ・棟の選択 | 無し |

対象外: 査定報告書の受け取り箱(置いた時点でサーバーに保存済み)/現地調査の画面(位置情報をブラウザに残さない既存方針 `pin-create-modal.tsx` を守る)/一覧の検索条件(要望の範囲外)。
保存しないもの: サーバーから取り直せる一覧・候補の検索結果キャッシュ・送信中フラグ以外の画面の一時状態(ドラッグ中など)・`File` オブジェクト・objectURL。

## 3. 動き方(利用者から見て)

1. 入力や読み取りをすると、**そのタブの中に自動で控える**(変更から約1秒後にまとめて/画面を離れる瞬間にも必ず1回)。
2. 同じ画面に戻ると、元の段階・内容で表示され、上に帯が出る:
   **「前回の続きを表示しています（◯時◯分の入力）」［最初からやり直す］**
3. 物件の編集は小窓。**その物件の画面に戻ると、編集の小窓が自動で開き直る**(続きがあるときだけ)。新規物件登録は、開いた元の画面(物件一覧/販売図面の新規作成)に戻ったとき同様に開き直る。新規物件登録の小窓は2か所から開くので、控えの鍵は開いた画面ごとに分ける(`new-property:properties` / `new-property:sales-sheet`)。
4. 控えを消すとき: 登録・保存・取り込みが**終わったとき**/「キャンセル」「最初からやり直す」/**ログアウト(自動ログアウト含む)**/タブを閉じたとき(sessionStorage の性質)/控えてから**12時間**たったとき。
5. ページの再読み込み(F5)でも残る(同じタブなので)。

## 4. 仕組み

### 4.1 共通の部品(新規)

- `src/lib/drafts/draft-store.ts` — 純関数+薄い保存層。
  - 鍵: `pm-draft:v1:<利用者ID>:<画面名>[:<物件ID>]`。画面名は定数の一覧(`DRAFT_SCREENS`)で固定。
  - 中身: `{ v: 1, savedAt: <ms>, data: <画面ごとのJSON>, pendingSubmit?: { at: <ms> } }`。
  - `readDraft(key, now)` は壊れたJSON・形の違い・12時間超・別の利用者の鍵を**無かったことにして消す**。
  - `writeDraft(key, data)`: JSON化した長さが **1,500,000文字**を超えたら書かずに `"too_large"` を返す。`QuotaExceededError` 等は握りつぶして `"failed"`。成功は `"ok"`。
  - `clearDraft(key)` / `clearAllDrafts()`(`pm-draft:` で始まる鍵をすべて消す)。
  - sessionStorage の読み書きはすべて try/catch(既存 `desk-step-guide.tsx` の型)。使えない端末では**何もしない**(これまでどおり消えるだけ・画面は壊れない)。
- `src/hooks/use-screen-draft.ts` — 画面用の hook。
  - `useScreenDraft<T>({ screen, resourceId?, enabled, serialize, isEmpty })` → `{ restored: T | null, restoredAt, pendingSubmitAt, save(), clear(), markSubmitting(), tooLarge }`。
  - 利用者IDは `useSession()` から。取れるまで読み書きしない。
  - 書き込みは約1秒の間引き+**画面を離れるとき(unmount)と `pagehide` で即時**。メニューでの移動は Next.js の画面切り替え=部品の unmount なので、ここで必ず書く。
  - `isEmpty(data)` が真(まだ何も入れていない)なら書かずに消す=空の控えを残さない。
- `src/components/drafts/draft-restored-notice.tsx` — 帯の部品(文言は §3-2)。SSRテストできる見た目だけの部品にする。

### 4.2 ログアウトでの片付け

`src/lib/notifications/logout.ts` の `signOutWithNotificationCleanup` で、`clearNoticeStorage()` の隣で `clearAllDrafts()` を呼ぶ。next-auth の `signOut` を直接呼ぶことは既存テストで禁じられているので、ここが全経路(手動・自動ログアウト・パスワード変更)の一か所。
加えて、ログアウトを通らずにセッションが切れて別の人がそのタブでログインした場合に備え、**鍵に利用者IDを入れ、読むときに他人の鍵は消す**。

### 4.3 各画面の組み込み

- 各画面の状態は今のまま(useState)で、**控えに入れる値の組み立て(serialize)と、控えから戻す処理(restore)だけを足す**。組み立て・戻しは画面ごとの純関数(`src/lib/drafts/screens/<画面>.ts`)にして、形の検査(zod)を通らない控えは捨てる。
- S5 物件の編集: 控え=`{ propertyId, baseVersion, changed: Record<string,string>, buildingChoice }`。戻すのは、既存の「物件が変わったら値を初期化する」処理(`property` を見る effect)の**あと**。`property.version !== baseVersion` なら戻さずに消し、帯の代わりに「ほかの方が保存したため、入力途中の内容は使えませんでした」と出す。編集の鍵(edit-lock)は**通常どおり取り直す**(控えは鍵を素通りしない)。小窓の自動再オープンは物件詳細の画面が控えの有無を見て行う。
- S1・S3 のファイル選び直し: 控えに `fileName` と「ファイルで読んだ」印を持つ。戻したとき、登録ボタンの手前に「PDF『◯◯』を選び直してください」と選択ボタンを出し、**選び直すまで登録ボタンは押せない**(S1 で PDF を添付しない場合と、S3 の文章貼り付けは不要)。選び直したファイルは読み取りし直さない(結果はそのまま)。名前が違えば確認文を出す。

## 5. 二重登録・大きさ・競合

### 5.1 送信中に離れた場合(最重要)

登録・取り込みの送信直前に `markSubmitting()` で控えに `pendingSubmit` を書き、結果が返ったら完了(=控えを消す)か失敗(=印を外す)にする。
戻ったときに `pendingSubmit` が残っていたら、**送った結果が分からない**ので、再送できる形では戻さない:
- S1/S3/S6: 「前回、登録の途中で画面を離れました。登録されたかどうかを物件一覧で確かめてください」と出し、内容は**見るだけ**で表示(［この内容でもう一度登録する］は利用者が確かめてから押す明示ボタン)。
- S4: 取り込みはサーバー側で続いている可能性 → 「取り込み履歴」への案内を出し、控えは消す。
- S5: 保存は版番号で守られている(同じ版で2回は通らない)ので、通常どおり戻し、版が変わっていれば §4.3 の扱い。

### 5.2 Excelから物件化(S2)の途中で離れた場合

- 画面を離れるとき、今の行で**登録の繰り返しを止める**(今は画面を離れても裏で送り続けうる)。
- 1行ずつ「送信中」→「結果」を控えに書く。戻ったとき「送信中」のままの行は**「登録されたか分かりません(一覧で確認)」**と表示し、まとめて登録の対象から外す(手で「この行も登録する」を押せる)。
- 登録済みの行の印は残り、もう一度押すと**残りだけ**を登録する。

### 5.3 タブの複製

ブラウザの「タブを複製」は sessionStorage を写し取るので、控えも2つのタブに写る。複製したタブでも同じ続きが出るのは利用者の操作どおりとして許容する。二重登録は §5.1・§5.2 と、既存の重複判定(貼り付けて物件化・Excel の重複チェック)で防ぐ。

### 5.4 大きすぎる場合

`writeDraft` が `"too_large"` を返したら、帯の位置に一度だけ「このファイルは大きいため、別の画面へ移ると消えます」と出す(S4 の数MB超のCSV/Excel、S2 の非常に大きいExcelを想定)。以後その作業中は書かない。

## 6. 守り(PII)

- 置き場は **sessionStorage のみ**(タブを閉じると消える)。localStorage・IndexedDB は使わない。
- 鍵に利用者ID・物件IDを含むが、**中身はサーバーの応答と同じ範囲**(画面にもともと出ている情報だけ)。新たにサーバーから取る情報は無い。
- ログアウトで全消し(§4.2)/12時間で失効/作業完了で消す。
- 控えの中身をログ・エラー表示・監査に出さない。
- サーバー側の変更は**無い**(API・DB・migration なし)。

## 7. テスト

- `draft-store`: 鍵の組み立て/12時間失効/他人の鍵を捨てる/壊れたJSON/大きさ上限/sessionStorage が例外を投げる環境/`clearAllDrafts` が `pm-draft:` 以外を消さない。(vitest node 環境なので、メモリ上の Storage の偽物を `globalThis.sessionStorage` に差して試す)
- 画面ごとの serialize/restore 純関数: 往復で同じになる/`File` が混ざらない/形の違う控えを捨てる/S5 の版違いで戻さない/`pendingSubmit` が残る場合の判定。
- S2 の行の状態判定(送信中のまま→要確認・まとめて登録から除外)は純関数で総当たり。
- 配線(ソース走査型): 各画面が `useScreenDraft` を使い、完了・キャンセル・やり直しで `clear()` を呼ぶ/送信前に `markSubmitting()` を呼ぶ/`logout.ts` が `clearAllDrafts()` を呼ぶ/対象外の現地調査画面が使っていない。
- 帯の部品: SSR で文言と［最初からやり直す］ボタン。
- 手元の実機(ローカル): 各画面で入力→別メニュー→戻る/F5/ログアウト→ログイン/タブを閉じて開き直す/送信直後に移動。

## 8. 進め方(PRの分け方)

1. **土台+入力の画面**: 共通部品・ログアウトの片付け・S6 新規物件登録・S5 物件の編集。
2. **読み取りの画面**: S1 貼り付けて物件化・S3 謄本PDF・S2 Excel・S4 CSV。
3. 使い方ガイド/マニュアルに一文足す(「作業の途中で別の画面へ移っても、同じタブなら続きから再開できます」)。

各段で @codex を通し、マージ後に本番反映(migration なし)。

## 9. リスク

| リスク | 対策 |
|---|---|
| 戻した値が古い(ほかの人が保存済み) | S5 は版番号で判定して捨てる。読み取り系は新規登録なので既存の重複判定で気づける |
| 送信の結果が分からないまま再送 | §5.1 `pendingSubmit` で再送できる形に戻さない |
| 控えの書き込みが重く入力がもたつく | 約1秒の間引き。大きい控えは書かない(§5.4) |
| 共用PCで次の人に見える | sessionStorage+ログアウト全消し+利用者IDの鍵+12時間失効 |
| 既存の「物件が変わったら初期化」処理に上書きされる | S5 は初期化の後に戻す順序をテストで固定 |
