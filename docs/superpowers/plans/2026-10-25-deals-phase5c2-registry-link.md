# 取引・帳票 段5c-2 謄本の「登記の現況」との連動

**Spec:** `docs/superpowers/specs/2026-10-23-deals-documents-design.md` §4.6.1

## Global Constraints
- DB の変更なし・新しい部品なし。判定結果は保存しない(開くたび・出すたびに読む)。
- 氏名・住所: 権利者名は「取引の閲覧」と「所有者の閲覧(owner:read)」の両方があるときだけ出す。債務者名は出さない。監査には件数だけ。
- テストに実在の個人情報を入れない。

## Rulings
1. 読む元 = 取引の物件の添付のうち、謄本(type=registry)・削除なし・所有者事項(owner)でないものを新しい順に最大5件見て、本文が全部事項(`isFullCertificateText`)の最初の1件。手で取り込んだ謄本は種別が空なので、本文で見分ける。物件が無い取引は何もしない。
2. 判定 = `summarizeRegistryRights({pdf, text})`。null・甲区を読めない・ファイルが無い/文字を読めない全部事項 → 「判定できない」=自動の項目は出さず「謄本を確認してください」だけ。
3. 取引の画面: タブの上に表示。残っている乙区の権利(順位・目的・債権額/極度額・権利者)、差押えなどの注意(甲区/乙区・順位・目的)、目視確認の注記。何も残っていなければ「残っていません」と1行。新しい口 `GET /api/deals/[id]/registry-rights`(取引の閲覧)。
4. 書類確認書: 頭に「登記の注意」行(注意・注記・判定できないときは「謄本を確認してください」)。決済時は、乙区の権利が残っていれば自動で3項目(事前に手配=司法書士への抹消の依頼/持参=抹消費用(金額=費用の抹消費用)/受け取る=抵当権抹消書類(金融機関))。持参の抹消費用は、設定の項目にすでに抹消費用の金額付き項目があれば足さない。
6. 謄本を読むのは、その物件を見られる人(物件の閲覧+担当範囲=物件を開くリンクと同じ判定)だけ。見られない人には何も読まない(画面は出さない・書類確認書に抹消の項目を足さない)。提出前レビューで、既存の謄本の画面より緩いと指摘されたため。
5. 発行・出せる書類の道では、書類確認書のときだけ謄本を読む(出せる書類の道は取引に物件があるとき1回)。読み取りの失敗は「判定できない」にして、書類は出す。
