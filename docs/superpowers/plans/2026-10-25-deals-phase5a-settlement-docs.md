# 取引・帳票 段5a(業務書類の土台+決済の書類=精算書・残金決済のご案内・領収書3種)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 取引の「書類」タブに、その取引で出せる業務書類を並べ、出す前に空欄の項目を見せてから、PDF と Excel(値だけ)で発行できるようにする。この段は決済の書類 5 つ。

**Architecture:** 業務書類の一覧表 `src/lib/deals/documents/registry.ts`(設計 §4.1)に、書類ごとに「出す条件・必要な項目・発行のときに選ぶもの・組み立て」を1行で持つ。発行は段3の道(保存場所・版・権限・後片付け)をそのまま使い、書類の種類で一覧表の組み立てを呼ぶ。金額はすべて段2の決済の計算(`settlementResult`)から取る(精算書・ご案内・精算金領収書で同じ値)。

**Spec:** `docs/superpowers/specs/2026-10-23-deals-documents-design.md` §4.1〜4.5・§4.7〜4.9・§6 段5 + 依頼書 4.3・4.4。

## Global Constraints

- DB の変更なし・新しい部品なし。
- 金額は段2の計算の値をそのまま使う(書類の中で計算し直さない)。
- 署名・実印の欄は常に空欄。売主が個人の領収書は、その人の名前・住所で出し、自社の角印は付けない。
- 領収書・お知らせは明朝、表と数字の書類はゴシック(設計 §4.2)。
- 業務書類の Excel は値だけ(設計 §4.8)。
- 監査には書類の種類・版だけ。名前・住所・金額は残さない。
- テストは架空データだけ。前職の文面は使わない。

## 読み替え(Rulings)

1. **段5を 5a・5b・5c の3つに分ける**(上の表)。設計 §6 の「多ければ PR を2つに分ける」を、書類の数と確認書の設定・謄本の連動の重さから3つにした。
2. **発行のときに選ぶもの(領収書の発行者・非課税の判断・日付・振込先・持ち物)は、取引には保存せず、発行の体で送って、発行履歴の入力の写しに残す。** 理由: 書類1枚ごとの選択で、取引のデータではない。履歴の写しで「その版を何で出したか」は分かる。
3. **出す前の確認は画面で行う。** サーバーは空欄があっても発行する(「空欄のまま出す」を選んだ人を止めない)。必要な項目の判定はサーバーの一覧表に1か所だけ持ち、画面はその結果を表示する(`GET /api/deals/[id]/documents/available`)。
4. **領収書の発行者:** 選べるのは「受け取る側」の当事者(手付金・残金=売主、精算金=差引で受け取る側)と自社。初期値は、その側に自社の当事者があれば自社、なければ最初の当事者。発行者が自社(または自社の当事者)なら会社名・代表者・角印、個人なら名前・住所だけで角印なし・署名押印の欄は空欄。法人の当事者は名前・代表者・住所で、角印は付けない(自社の角印は自社のときだけ)。
5. **領収書の印紙:** 受取書の表で税額を出す。発行者が個人のときは「非課税(事業用でない)」か「課税」を発行のときに必ず選ぶ(初期値は選んでいない=決めるまで発行ボタンを押せない。設計 §4.3)。発行者が自社・法人のときは課税。書類には「収入印紙 ○円」の枠か「非課税」を出す。
6. **精算書の2枚目:** まず計算の過程(計算期間・計算式)を入れた1枚の形で PDF を作り、ページ数を数える。2ページ以上なら、1枚目は項目と金額と合計だけにし、計算の過程を2枚目の「計算明細」に回して作り直す(設計 §4.5 の「一度組み立ててから高さを測る」を、PDF のページ数で測る形にした)。
7. **残金決済のご案内の金種明細 = 精算書の「残代金+精算金−敷金承継=決済時のお支払額」と同じ数字。** 依頼書の「−諸費用」は、登記費用などを買主から司法書士へ払う別の支払いのため、この明細には入れず「登記費用などは別途、司法書士へお支払いください」と添える。振込先は、売主が自社なら取引の設定の口座を初期値にし、発行のときに直せる(売主が他社・個人なら空欄を初期値)。持ち物は一般的な項目を初期値にし、発行のときに直せる。宛先は買主。
8. **手付金領収書 = 手付金、残金領収書 = 売買価格−手付金、精算金領収書 = 精算書の差引の額**(内訳は精算書の項目名)。差引が 0 のときは精算金領収書を一覧に出さない。
9. **業務書類の版の番号は (取引, 書類) ごと**(variant は `default`)。

## Review Focus

1. 精算書・ご案内・精算金領収書の金額が食い違わない(同じ計算の値)。
2. 個人の売主の領収書に自社の角印・会社名が入らない。署名・押印の欄が空欄。
3. 非課税の判断をしないと個人発行の領収書を発行できない(サーバーも 422)。
4. 当てはまらない行(管理費は区分だけ・賃料と敷金は OC だけ)が精算書に出ない。
5. 2枚目の計算明細に回したときも、1枚目に各項目の金額と合計がある。
